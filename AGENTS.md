# AGENTS.md

Single-file Python tool: `autoporter.py` builds `super.img` from Xiaomi OTA(s) + 2 GDrive mod archives. No packages, tests, lint, or typecheck.

## Run
- `pip install -r requirements.txt` (needs `requests`, `tqdm`)
- CI reference (`.github/workflows/port.yml`, manual `workflow_dispatch` only): Python 3.10 on `ubuntu-latest` + `sudo apt-get install -y android-sdk-libsparse-utils erofs-utils p7zip-full wget curl default-jre-headless` (JRE needed for the baksmali/smali step). Checkout uses `lfs: true` — without it `template/images/*.img` + `Modules_Root/*.zip` check out as 130-byte LFS pointers and end up broken in the package.
- Full run: `sudo python -u autoporter.py` (root is load-bearing: only as root does extraction restore owners/xattrs onto the trees, which the contexts pipeline needs; CI-only `sudo pip install --break-system-packages`) — downloads ~tens of GB, do NOT run casually to "verify"; there is no quick/single-test mode. `-u` (unbuffered) is load-bearing: without it, Python block-buffers stdout to the CI pipe and child-tool stderr (lpmake, unbuffered) appears *earlier* in logs than the step that ran before it. CLI: `--mode port|mod` (default `port`; workflow `choice` input — `port` mixes stock+port OTAs, `mod` modifies the full stock firmware only, no donors, no port OTA download), `--hyper-version hos3|hos4` (default `hos4`), `--package-type universal|fastboot-only` (default `universal`; workflow exposes both as `choice` inputs), `--debloat auto|hos3|hos4|none` (default `auto` = match `--hyper-version`; workflow `choice` input), `--dsv yes|no` (default `yes`; workflow `choice` input — gates ONLY the signature-verification lists via `signature_patch_lists()`; functional smali fixes always apply), `--decrypt-data yes|no` (default `no`; workflow `choice` default `yes`), `--density` (default `480`; workflow `number` input — written as `persist.miui.density_v2` + `ro.sf.lcd_density` into `product/etc/build.prop`), `--aod-fullscreen true|false` (default `true`; workflow `choice` input — `support_aod_fullscreen` in `duchamp.xml` + `NoSuchElementException` catch in `miui-services.jar`), `--ext4-rw` (comma list/`all`/`none`, default `product,system`; workflow `string` input) + `--ext4-free-mb` (default `150`; workflow `number` input).

## What the script does (order matters)
1. `setup_tools()`: mkdirs `tools/ moddedapps_hos3/ moddedapps_hos4/ extracted_stock/ extracted_port/ unpacked_stock/ unpacked_port/ port_meta/`, `chmod +x` on `tools/*`, prepends `tools/` to `PATH`.
2. Downloads the selected mod set via direct link (`--hyper-version hos3|hos4`, default `hos4`; workflow `choice` input; release assets on GitHub, no auth/quotas — GDrive was dropped after Drive flagged the archives), unpacks with `shutil.unpack_archive` falling back to `7z x` (requires `p7zip-full`), flattens single top-level dir, wipes stale dest names before move (re-runs safe), prints top-level layout, normalizes modes (`normalize_tree_perms()`: dirs 0755, files 0644, symlinks untouched, best-effort chown root:root when root — zips carry arbitrary modes), deletes zip.
3. `process_firmware()`: downloads OTA zip → extracts only `payload.bin` (+ `META-INF/com/android/metadata{,.pb}` → `port_meta/`, before zip deletion) → **deletes zip immediately** → dumps partitions via `payload-dumper-go -q` (output captured, only tail shown on failure) → **deletes payload.bin immediately**. Disk-saving deletions are load-bearing; keep them. Port mode: stock → `extracted_stock/`, port → `extracted_port/` (separate dirs: stock extras share names with port partitions and would overwrite each other). Mod mode: full stock set (`MOD_PARTITIONS`) → `extracted_stock/` only, its own `META-INF` → `port_meta/`, no port OTA download.
4. `unpack_partitions()`: port mode unpacks stock `.img` (incl. extras) → `unpacked_stock/<name>/`, port `.img` → `unpacked_port/<name>/`; mod mode unpacks `MOD_PARTITIONS` → `unpacked_stock/<name>/` only (fresh extract, stale content wiped). Format by magic: ext4 via `debugfs rdump` (e2fsprogs, preinstalled), erofs via vendored `tools/fsck.erofs --extract --xattrs` (dev build + killpriv-order fix: restores owners/modes/xattrs as root; falls back to system fsck without `--xattrs` on tooling failure, data errors always raise), sparse via `simg2img` if present. uid/gid/xattrs are NOT preserved by `debugfs rdump` (native ext4) — only erofs trees carry them.
4b. `flatten_pangu_system()`: moves `<product>/pangu/system/*` up into `<product>/` (stock AND port OTAs nest product content there — pangu exists in duchamp stock too), merging dirs recursively, dropping the empty nesting; no-op when absent. Port mode flattens both `unpacked_port/product/` and `unpacked_stock/product/` (donors are read from the stock tree, so without it they would miss into `pangu/`; stock product is donors-only, never rebuilt), mod mode flattens `unpacked_stock/product/`. Runs before donors+debloat so all paths match the final flat layout.
4c. `apply_donor_files()`: port mode only — copies stock donor blobs into the port tree — `DONOR_FILES` (currently `product/etc/device_features/duchamp.xml` as-is; extend per device), `DONOR_DIRS` merged recursively (currently `product/etc/displayconfig`), `DONOR_DIR_FILES` (currently 4 APEXes from `system_ext/apex` + 4 overlays from `product/overlay`: `AospFrameworkResOverlay`, `DevicesAndroidOverlay`, `DevicesOverlay`, `MiuiFrameworkResOverlay`). Mod mode skips donors entirely (full stock, nothing to carry over). Missing sources only warn; runs before debloat+rebuild.
4c2. `apply_modded_apps()`: overlays the extracted mod set onto the target tree — port mode into `unpacked_port/`, mod mode into `unpacked_stock/` — each top-level partition dir (`product/`, `system/`, `system_ext/`, ...) merged recursively via `copy_tree_into()` (symlinks preserved, modded files replace existing ones; `system/` keeps its nested `system/` level on both sides). Runs after donors+flatten, before debloat, so oat strips and deletions apply to the final content. Missing partition dirs on either side only warn.
4c3. `apply_mi_ext_tweaks()` on the build tree (`patch_root`, both modes — `mi_ext` is the port's in port mode, the stock's in mod mode): patches `mi_ext/etc/build.prop` (`ro.product.mod_device=duchamp` set/appended, `MI_EXT_DROP_PROP_KEYS` removed by key, `ro.vendor.radio.5g=3` only when present, `ro.mi.os.version.incremental` value prefixed with `TengeOS | ` when present, `ro.miui.support.system.app.uninstall.v2` moved into `product/etc/build.prop` via upsert), moves uninstall blobs from the nested `mi_ext/product/` into `product/` (`MI_EXT_PRODUCT_MOVES`: `platform-miui-uninstall.xml` always, `rustruntime_cfg_v3_v5.xml` only when `--hyper-version hos4`, `miui-uninstall-empty.jar`; moves preserve xattrs/symlinks via `move_file_preserve()`, emptied parents dropped best-effort), deletes `mi_ext/system` + `mi_ext/system_ext` + `mi_ext/product/app`, and deletes `product/etc/permissions/cn.google.services.xml` (not debloat-gated, like fstab). Missing sources only warn; runs before debloat.
4c3b. `apply_about_phone_description()` on the build tree (`patch_root`, both modes): copies the committed `about_phone_description/duchamp/` overlay in — `product/etc/device_info.json` → `product/etc/` always, `system/system/priv-app/HTMLViewer/HTMLViewer.apk` → `system/system/` only when `--hyper-version hos3`. Copy (not move — the overlay is repo content) with xattrs/symlinks via `copy_file_preserve()` (existing dests replaced); missing sources only warn; runs before debloat.
4c3c. `apply_init_rc_tweak()` on the build tree (`patch_root`, both modes): appends the `animationfix` block once to the end of `system/system/etc/init/hw/init.rc` (SAR-nested; `on property:sys.boot_completed=1` → `start animationfix`, `service animationfix` forcing `deviceLevelList` via `settings put`). Idempotent (guard line `service animationfix` skips re-runs); missing file only warns; runs before debloat+rebuild.
4c4. `apply_build_prop_tweaks()` on the build tree (`patch_root`, both modes): writes `--density` into `product/etc/build.prop` (`persist.miui.density_v2` + `ro.sf.lcd_density`), appends `PRODUCT_PROP_APPEND` (blur flags, handy mode, uninstall flag) to product and `SYSTEM_PROP_APPEND` (gmscore, opa, dex2oat speed block with comment) to `system/system/build.prop` (SAR-nested in both trees), and normalizes `ro.product.locale=en-US` + `ro.build.host=wectazz` in both. Upsert semantics (replace in place, else append at end — exact block order on fresh trees, idempotent); missing files only warn.
4c5. `patch_device_features()` on the build tree (`patch_root`, both modes — in port mode the file arrives via donors, so this runs after them): applies the `duchamp_mod.xml` tweaks to `product/etc/device_features/duchamp.xml` — `support_aod_fullscreen` set/inserted per `--aod-fullscreen` (+ always-on `support_aod_aon`), `is_only_support_keycode_goto=false`, second `aod_support_keycode_goto_dismiss` false→true (first occurrence is already true, matched by value so it stays untouched), `support_screen_enhance_engine` + `support_AI_display` inserted after `default_eyecare_mode`, `90Hz` item added to `fpsList`, `defaultFps=120`. Line-based, everything else byte-identical (proven: patch of stock is byte-identical to the mod file); idempotent; missing file only warns.
4c6. `apply_vibrator_fix()` on the unpacked stock tree (port mode only — `odm` exists only in stock; not dsv-gated, it's a functional port fix): hos3→hos4 vibrator fix — `/vibratorfeature` → `/default` in the vintf manifest `odm/etc/vintf/manifest/vendor.xiaomi.hardware.vibratorfeature.service.xml`, and the same replacement NUL-padded to equal length in the hw service binary `odm/bin/hw/vendor.xiaomi.hardware.vibratorfeature.service` (size kept; exactly-1 occurrence patched, anything else warn-skipped). The services.jar half rides the smali step below.
4d. `apply_debloat()` + `apply_stock_debloat()`: port mode deletes the `DEBLOAT` list entries for the selected version from the unpacked port tree; mod mode applies the same `DEBLOAT` list onto the unpacked stock tree instead (`mi_ext` entries just warn-missing when absent) — `STOCK_DEBLOAT` always goes onto the unpacked stock tree (currently `vendor/etc/voicecommand` + `vendor/etc/thermal` — vendor exists only in stock, never in port). Entries resolve case-insensitively per path component via `_resolve_insensitive()` (exact match wins; OEMs shuffle capitalization like `MIPay`/`MIpay`; resolved renames are logged as `[case]`). Paths are relative to `unpacked_port/` / `unpacked_stock/` (NOT `extracted_*` — those hold `.img` files). Missing entries only warn (OTAs differ); runs before the rebuild bakes the trees in. Same step also runs `patch_vendor_fstab()` (DNA rw/decrypt port): strips AVB options from `vendor/etc/fstab.*` lines, drops `overlay` lines (rw), and with `--decrypt-data yes` renames `fileencryption` → `fileencryptable` (AVB strips run first so the renamed option can't dodge them).
4e. `patch_jar_smali()`: decompiles `system/system/framework/framework.jar` per-dex with `tools/baksmali.jar` (`--api` from each dex header via `DEX_VERSION_API`), injects `dsv/framework/<dex>/*.smali` at the path from its own `.class` (currently `XdConfig` → `classes6/android/os/`; skips classes already present), applies `FRAMEWORK_METHOD_PATCHES` (body → `XdConfig` call) + `FRAMEWORK_INSERT_PATCHES` (insert after invoke), reassembles with `tools/smali.jar` and swaps the dexes back into the jar (other entries byte-identical, atomic replace). Missing files/methods only warn. Needs `java` (CI: `default-jre-headless`). Source tree is `unpacked_port/` in port mode, `unpacked_stock/` in mod mode (`patch_root`). Every rule here is signature-verification, so the whole step runs only with `--dsv yes`. LIMIT: jars are v3.0.10 (latest) — dex 041 is attempted, 042+ fails fast (no valid `--api`; 36+ writes zeroed headers). Every dex is verified after rebuild (magic + class count vs intake, since both tools exit 0 even on failure). Stale precompiled code is dropped per target: whole `oat/` next to every patched APK, but only `<name>.odex/.vdex/.art` in `oat/arm64/` next to patched jars (`oat/` holds other jars' valid outputs too). Device recompiles on first boot via odrefresh/dalvik-cache. Host-side dex2oat is deliberately NOT done: real dex2oat is an ARM ART binary (CI is x86_64) needing qemu + ART sysroot + the firmware's own bootclasspath — version-mismatched oat = bootloop, unverifiable without a device.
4f. Same `patch_jar_smali()` on `system_ext/framework/miui-services.jar` (under `patch_root`) with `MIUI_SERVICES_METHOD_PATCHES` (void bodies, no `XdConfig` call — signature, dsv-gated) + `MIUI_SERVICES_START_PATCHES` (insert secure-flag bypass block at the start of `notAllowCaptureDisplay`, matched by name + descriptor + body markers, unique `:bypass_secure_flag` label since baksmali renumbers `:cond_N` itself — functional, always applied) + `MIUI_SERVICES_REPLACE_PATCHES` (literal field swap `IS_INTERNATIONAL_BUILD` → `IS_MIUI` for notifications on Chinese ROMs — functional, always applied; no dsv dir yet — injection skips gracefully) + Baidu→Gboard keyboard strings in `InputMethodManagerServiceImpl` (functional, always applied, both modes) + `MIUI_SERVICES_DRM_REPLACE_PATCHES` (4-line `DrmBroadcast` sequence in `ActivityManagerServiceImpl` deleted outright — functional, always applied) + `MIUI_SERVICES_AOD_CATCH_PATCHES` (`.catch Ljava/util/NoSuchElementException;` inserted after the `SecurityException` catch whose previous `.catch` is `RemoteException` with the same try range + handler — fullscreen-AOD fix, gated by `--aod-fullscreen` like the xml flag, NOT dsv-gated; try/catch labels captured from the file so hos3/hos4 numbering doesn't matter, `*.smali` scan since the owning class isn't pinned, idempotent; missing anchor only warns). All dsv rules apply to hos3 and hos4 alike (no version branching).
4f2. Same `patch_jar_smali()` on `system_ext/framework/miui-framework.jar` (under `patch_root`, both modes, always) with keyboard strings in `InputMethodServiceInjector` only (no dsv dir — injection skips gracefully; missing jar only warns).
4g. Same `patch_jar_smali()` on `system/system/framework/services.jar` (under `patch_root`) with `SERVICES_METHOD_PATCHES`: `checkUpgradeKeySetLocked` + signature-match methods (keep original `.registers`, body → `XdConfig` call), `checkDowngrade` overloads (void stubs), `<clinit>` (full custom block forcing `ALLOW_NON_PRELOADS_SYSTEM_SHAREDUIDS=true`). Rules support fixed or kept registers plus custom body lines. `SERVICES_START_PATCHES` (secure-flag bypass at method start: empty-list variant for `WindowManagerService.notifyScreenshotListeners`, false variant for `WindowState.isSecureLocked`) + `SERVICES_NEW_METHODS` (brand-new `WindowState.isBypassSecureFlag()` reading `persist.sys.secure_flag`, inserted before `isLegacyPolicyVisibility`, skipped if already present). Plus `SERVICES_VIBRATOR_REPLACE_PATCHES` in port mode only (hos3→hos4 vibrator fix: 4-line `MiuiStubUtil.getImpl` sequence in `VibratorManagerServiceStub$Holder` → direct `new-instance`+`<init>`, via the literal whole-file replace). All three jar steps run only with `--dsv yes` (default; workflow `choice` input `dsv: "yes"|"no"`); `"no"` skips the DSV lists only (functional fixes still apply to all jars).
4g2. `patch_apk_smali()` (extended keyboard, always, both modes): full `tools/apkeditor.jar` decode → literal whole-file replaces on the decoded `smali/` tree → rebuild, with checks (decode must yield smali, rebuilt entry-name set must equal the original, atomic replace). Work dir is a system-temp dir (NOT the repo — slow mounts stall thousand-file decodes and litter on kills), wiped in `finally`. Internal dex lib handles dex up to 042 (unlike the jar tools). Rules: Baidu→Gboard strings in `product/app/MIUIFrequentPhrase/MIUIFrequentPhrase.apk` (`InputMethodBottomManager`) and `system_ext/priv-app/Settings/Settings.apk` (`AvailableVirtualKeyboardFragment`), plus a `const/4 v0, 0x1` after the `getInt` `move-result` in `InputMethodFunctionSelectUtils` (force IME-bottom support; blank-line-exact block, proven against real Settings smali). Each call drops the stale `oat/` next to the APK (dex was rebuilt). NOTE: the rebuild refreshes signatures; DSV neuters the checks like with modded-apps overlays. Missing APKs only warn.
4h. `move_data_app_to_app()`: moves `product/data-app/*` into `product/app/` on the build tree (`patch_root`), merging dirs recursively via `merge_tree_into()` (existing entries replaced). Runs last, right before the rebuild, so debloat leftovers, DSV and modded apps all land in `app/`; no-op when `data-app/` is absent.
4i. `build_sidecars()`: writes `<part>.fs_config` + `<part>.file_contexts` next to each target `.img` for erofs→ext4 conversions, and `<part>.file_contexts` only for erofs→erofs rebuilds (uid/gid/mode/caps come from the tree itself at mkfs time, no fs_config needed); native ext4 keeps the legacy build with no sidecars. `fs_config` = `/ 0 0 0755` + `<part>/<rel> uid gid mode [capabilities=0x..]` walked live from the final tree (dirs, files AND symlinks — symlinks consume inodes too, omitting them starved system builds, proven by CI); `file_contexts` = `/` + own `etc/selinux/*_file_contexts` + plat/vendor fallbacks (specific-first, dedup), ROM lines filtered by an allowlist grammar (safe path/context chars incl. `(a|b)` alternations, `[^/]`/`[0-9]` classes and `@` in HAL names, optional known file-kind, plus a compile check — an uncompilable pattern like unbalanced `[` fails lookups with cryptic errors, proven by bisecting a real file down to one poison line; anything else is dropped and logged, while `$` tiers keep every path covered regardless), exact paths converted to `(/.*)?` pattern form (`+` escaped) since this lookup only matches patterns, plus explicit `lost+found` entries (mke2fs creates it, e2fsdroid fails fast on a miss) and `$`-anchored entries for every dir/file/symlink in the tree, ordered truth (dumped from the tree itself — wins over everything), ROM patterns, inherit (nearest resolved parent, else `system_file` root). `$` paths escape all regex metacharacters (`libc++.so`, `x(1).apk`, `y[2].bin` never match themselves otherwise — proven). Stock policy files don't cover every path (whole priv-app castes proven uncovered in CI) — without the inherit tier the build could never go green; `$` lines match exactly their path so tiers can't shadow each other wrongly. The per-partition log line reports the truth/inherit split. Runs on final trees right before the rebuild; missing sources only warn (→ legacy build).
5. `rebuild_partition_images()`: rebuilds `.img` in place from (patched) trees — port mode: port list → `extracted_port/`, `STOCK_PARTITIONS` only → `extracted_stock/` (donor extras `product`/`system_ext` in `unpacked_stock/` are never rebuilt); mod mode: full `MOD_PARTITIONS` set → `extracted_stock/` from the single stock tree. Format matches original by magic: erofs via vendored `tools/mkfs.erofs` (`-z<COMP> -T<fix> --mount-point=/<part> --file-contexts`, owners/modes/caps from the tree; unmatched files stay unlabeled, no fail-fast here unlike e2fsdroid) when its sidecar exists, else legacy system `mkfs.erofs -z<COMP>`, ext4 via vendored AOSP `tools/mke2fs` (empty fs: `-L -I 256 -N <lines+8> -M /<part> -m 0 -b 4096`, journal KEPT — diverges from packer/UKA `^has_journal` deliberately) + `tools/e2fsdroid -e -T1230768000 -C -S -f -a` (populate/label; `-s` dedup only for non-RW) when sidecars exist, else legacy `mkfs.ext4 -d` (size = max(original, tree*1.1+32MB)). Partitions in the `--ext4-rw` set are forced to ext4 regardless of original format, sized tree + free_mb + 128MB margin with `-m 0 -b 4096` (no root reserve so the free MBs are really visible; explicit `-b` because mke2fs silently picks 1K blocks on small filesystems); anything outside the set keeps legacy behavior. Build goes to `<name>.img.new` + atomic rename, so failures keep the old image.
5b. `main()` deletes `unpacked_stock/` + `unpacked_port/` right after the rebuild — nothing below uses them, and lpmake needs ~super_size bytes free next.
6. `repack_super_image(stock_dir, port_dir, ...)` [+ `mod_partitions` in mod mode]: logs every image size + `df` of the output dir, then fail-fast `RuntimeError` (clear message) when free < super+512MB — without it lpmake dies with cryptic `sparse_file_write failed (error code -22)`. `lpmake --metadata-slots 3 --virtual-ab` (no `--sparse` — raw `super.img`), groups `qti_dynamic_partitions_a` (same size for `_b`), 4096-byte alignment, tight packing (groups fit the partitions exactly, super = group total + 1MB lpmake metadata minimum — proven locally: anything less fails with exit 70; no snapshot padding, no GiB rounding; explicit `--device super:SIZE:4096` — without it lpmake pads ~1MB per partition and tight groups fail on the last one; each image pre-padded to 4096 with truncate so partition size == file size, since short reads fail under explicit alignment). lpmake output is captured (it probes every raw image as sparse → "Invalid sparse file format" noise is expected and harmless; only tail shown on failure, plus `df` at failure). Every partition is added twice: `<name>_a` with the real image, `<name>_b` as empty size-0 placeholder (no `--image` — unpacks as 0-byte file). Partition attr is `none` (not `readonly` — matches stock VAB + UnpackerSuper/UKA packing; `readonly` is for retrofit devices). Group sum may exceed super size; allowed under `--virtual-ab` (COW).
7. `assemble_package()`: fresh copy of committed `template/` → `package/`, `super.img` split into exactly 54 sparse chunks `images/super.img.0..53` (UKA/img2simg method, pure-Python port in `split_file()`: each chunk = sparse header + DONT_CARE offset + RAW data, so fastboot/recovery place every part correctly; raw slices would all land at offset 0. Sizing is exactly UKA — chunk = ceil(size_in_MB/54) whole MB, last takes the remainder (53 full + smaller last); names unpadded to match the scripts). `package_type="universal"` keeps `META-INF` (updater-script + update-binary, OTA metadata copied over `META-INF/com/android/` — port metadata in port mode, stock metadata in mod mode); `"fastboot-only"` deletes the whole `META-INF` dir and skips the metadata copy.
8. `create_recovery_zip()`: packs `package/` into `HyperOS-<port|mod>-duchamp-<ver>[-fastboot-only].zip` with DEFLATE-9 (max). The universal ZIP is flashable in TWRP/OrangeFox (updater-script + ARM update-binary already in `template/`); the fastboot-only ZIP is a plain archive — unzip and run the install scripts. CI uploads only the ZIP (`super.img` stays local to the run for chunking); on failure it also uploads `extracted_*/<part>.fs_config` + `.file_contexts` sidecars as debug artifacts.

## Hardcoded inputs
- Stock (duchamp, HyperOS 3): `odm vendor odm_dlkm system_dlkm vendor_dlkm` (+ extras `product system_ext`, dumped/unpacked for reference only, never packed into super)
- Port (chagall, HyperOS 4): `mi_ext product system system_ext`
- Mod (`--mode mod`): full stock set `MOD_PARTITIONS` = `STOCK_PARTITIONS` + missing `PORT_PARTITIONS` names (all 9 from `STOCK_URL`, same order as the port super layout)
- Firmware URLs (`STOCK_URL`/`PORT_URL`) and mod-set URLs (`HOS3_MOD_URL`/`HOS4_MOD_URL`, GitHub release assets) are constants at top of `autoporter.py`.
- HyperOS `system.img` root contains a nested `system/` dir (`unpacked_port/system/system/app/...`, SAR-style). `moddedapps_hos*/system/system/...` mirrors it — the extra level is correct, do not "flatten" it. Other partitions (`product`, `system_ext`, ...) are flat at root.
- EROFS rebuild uses `EROFS_COMPRESSOR = "lz4hc,9"` (fast + safe; `"lzma,9"` also readable on the 6.1 kernel since MicroLZMA needs 5.16+, but builds much slower). Do NOT switch to deflate: it needs 6.6+ — unreadable images = bootloop.

## Gotchas
- `tools/` holds Linux x86-64 ELFs (`lpmake`, `lpunpack`, `payload-dumper-go`, `chunk_split`, AOSP `mke2fs`, `e2fsdroid`, dev-build `fsck.erofs` with xattr restore + killpriv-order fix, dev-build `mkfs.erofs` with selinux) + Java jars (`baksmali.jar`, `smali.jar`, `apktool.jar`, `apkeditor.jar` 1.4.9 for APK smali patching) committed to repo — ELFs won't run on Windows/macOS; use WSL2 or CI. `lpunpack` is currently unused. `lpmake` is a modern build (android-15 line, handles images >= 4GiB) and needs only system libc — the previous ancient static blob crashed with `sparse_file_write failed (error code -22)` on any 4GiB(-exact) dense data run (32-bit length wrap → zero-length chunk → `mmap(0)` → EINVAL, exit 73; proven with a local 4GiB-exact repro). Do NOT downgrade it.
- `7z` must exist for non-standard GDrive archives; `shutil.unpack_archive` alone is insufficient. Do NOT use `7z x` for ext4 images — it rewrites absolute symlink targets; `debugfs rdump` preserves them.
- No `extract.erofs` exists upstream (erofs-utils ships only `dump/fsck/mkfs.erofs`) — extraction is `fsck.erofs --extract`, which exists in both 1.7.1 (CI noble) and 1.9. Do NOT switch to `dump.erofs --cat`: it is missing in 1.7.1 and would break CI.
- `tools/` holds only what apt cannot provide (`lpmake`, `lpunpack`, `payload-dumper-go`, `chunk_split`, Java jars, plus `e2fsdroid`, AOSP `mke2fs` and the xattr-capable dev `fsck.erofs` for the contexts pipeline). Everything else (`dump`/`mkfs.erofs`, `simg2img`, `debugfs`, `7z`, JRE) comes from the apt list in `port.yml` — do not vendor them. `dsv/` (smali sources injected into jars, e.g. `XdConfig`) IS committed like `template/`.
- CI frees disk first (removes dotnet/android-sdk/ghc/boost, `docker image prune`) — full local runs need similar headroom.
- Outputs (`*.zip *.img *.bin`, `moddedapps_hos*/`, `extracted_stock/`, `extracted_port/`, `unpacked_stock/`, `unpacked_port/`, `package/`, `port_meta/`) are gitignored; only `super.img` is uploaded as artifact. `template/` IS committed (negations `!template/**/*.img|zip` keep its payload visible to git despite the rules above).
