# AGENTS.md

Single-file Python tool: `autoporter.py` builds `super.img` from Xiaomi OTA(s) + 2 GDrive mod archives. No packages, tests, lint, or typecheck.

## Run
- `pip install -r requirements.txt` (needs `requests`, `tqdm`)
- CI reference (`.github/workflows/port.yml`, manual `workflow_dispatch` only): Python 3.10 on `ubuntu-latest` + `sudo apt-get install -y android-sdk-libsparse-utils erofs-utils p7zip-full wget curl default-jre-headless` (JRE needed for the baksmali/smali step). Checkout uses `lfs: true` — without it `template/images/*.img` + `Modules_Root/*.zip` check out as 130-byte LFS pointers and end up broken in the package.
- Full run: `python -u autoporter.py` — downloads ~tens of GB, do NOT run casually to "verify"; there is no quick/single-test mode. `-u` (unbuffered) is load-bearing: without it, Python block-buffers stdout to the CI pipe and child-tool stderr (lpmake, unbuffered) appears *earlier* in logs than the step that ran before it. CLI: `--mode port|mod` (default `port`; workflow `choice` input — `port` mixes stock+port OTAs, `mod` modifies the full stock firmware only, no donors, no port OTA download), `--hyper-version hos3|hos4` (default `hos4`), `--package-type universal|fastboot-only` (default `universal`; workflow exposes both as `choice` inputs), `--debloat auto|hos3|hos4|none` (default `auto` = match `--hyper-version`; workflow `choice` input), `--dsv yes|no` (default `yes`; workflow `choice` input — gates all smali patching), `--decrypt-data yes|no` (default `no`; workflow `choice` input), `--ext4-rw` (comma list/`all`/`none`, default `product,system`; workflow `string` input) + `--ext4-free-mb` (default `150`; workflow `number` input).

## What the script does (order matters)
1. `setup_tools()`: mkdirs `tools/ moddedapps_hos3/ moddedapps_hos4/ extracted_stock/ extracted_port/ unpacked_stock/ unpacked_port/ port_meta/`, `chmod +x` on `tools/*`, prepends `tools/` to `PATH`.
2. Downloads the selected mod set via direct link (`--hyper-version hos3|hos4`, default `hos4`; workflow `choice` input; release assets on GitHub, no auth/quotas — GDrive was dropped after Drive flagged the archives), unpacks with `shutil.unpack_archive` falling back to `7z x` (requires `p7zip-full`), flattens single top-level dir, wipes stale dest names before move (re-runs safe), prints top-level layout, normalizes modes (`normalize_tree_perms()`: dirs 0755, files 0644, symlinks untouched, best-effort chown root:root when root — zips carry arbitrary modes), deletes zip.
3. `process_firmware()`: downloads OTA zip → extracts only `payload.bin` (+ `META-INF/com/android/metadata{,.pb}` → `port_meta/`, before zip deletion) → **deletes zip immediately** → dumps partitions via `payload-dumper-go -q` (output captured, only tail shown on failure) → **deletes payload.bin immediately**. Disk-saving deletions are load-bearing; keep them. Port mode: stock → `extracted_stock/`, port → `extracted_port/` (separate dirs: stock extras share names with port partitions and would overwrite each other). Mod mode: full stock set (`MOD_PARTITIONS`) → `extracted_stock/` only, its own `META-INF` → `port_meta/`, no port OTA download.
4. `unpack_partitions()`: port mode unpacks stock `.img` (incl. extras) → `unpacked_stock/<name>/`, port `.img` → `unpacked_port/<name>/`; mod mode unpacks `MOD_PARTITIONS` → `unpacked_stock/<name>/` only (fresh extract, stale content wiped). Format by magic: ext4 via `debugfs rdump` (e2fsprogs, preinstalled), erofs via vendored `tools/fsck.erofs --extract --xattrs` (dev build + killpriv-order fix: restores owners/modes/xattrs as root; falls back to system fsck without `--xattrs` on tooling failure, data errors always raise), sparse via `simg2img` if present. uid/gid/xattrs are NOT preserved by `debugfs rdump` (native ext4) — only erofs trees carry them.
4b. `flatten_pangu_system()`: port mode only. Moves `unpacked_port/product/pangu/system/*` up into `unpacked_port/product/` (the port OTA nests product content there), merging dirs recursively, dropping the empty nesting; no-op when absent. Runs before debloat so debloat paths match the final flat layout.
4c. `apply_donor_files()`: port mode only — copies stock donor blobs into the port tree — `DONOR_FILES` (currently `product/etc/device_features/duchamp.xml` as-is; extend per device), `DONOR_DIRS` merged recursively (currently `product/etc/displayconfig`), `DONOR_DIR_FILES` (currently 4 APEXes from `system_ext/apex` + 4 overlays from `product/overlay`: `AospFrameworkResOverlay`, `DevicesAndroidOverlay`, `DevicesOverlay`, `MiuiFrameworkResOverlay`). Mod mode skips donors entirely (full stock, nothing to carry over). Missing sources only warn; runs before debloat+rebuild.
4c2. `apply_modded_apps()`: overlays the extracted mod set onto the target tree — port mode into `unpacked_port/`, mod mode into `unpacked_stock/` — each top-level partition dir (`product/`, `system/`, `system_ext/`, ...) merged recursively via `copy_tree_into()` (symlinks preserved, modded files replace existing ones; `system/` keeps its nested `system/` level on both sides). Runs after donors+flatten, before debloat, so oat strips and deletions apply to the final content. Missing partition dirs on either side only warn.
4d. `apply_debloat()` + `apply_stock_debloat()`: port mode deletes the `DEBLOAT` list entries for the selected version from the unpacked port tree; mod mode applies the same `DEBLOAT` list onto the unpacked stock tree instead (`mi_ext` entries just warn-missing when absent) — `STOCK_DEBLOAT` always goes onto the unpacked stock tree (currently `vendor/etc/voicecommand` + `vendor/etc/thermal` — vendor exists only in stock, never in port). Paths are relative to `unpacked_port/` / `unpacked_stock/` (NOT `extracted_*` — those hold `.img` files). Missing entries only warn (OTAs differ); runs before the rebuild bakes the trees in. Same step also runs `patch_vendor_fstab()` (DNA rw/decrypt port): strips AVB options from `vendor/etc/fstab.*` lines, drops `overlay` lines (rw), and with `--decrypt-data yes` renames `fileencryption` → `fileencryptable` (AVB strips run first so the renamed option can't dodge them).
4e. `patch_jar_smali()`: decompiles `system/system/framework/framework.jar` per-dex with `tools/baksmali.jar` (`--api` from each dex header via `DEX_VERSION_API`), injects `dsv/framework/<dex>/*.smali` at the path from its own `.class` (currently `XdConfig` → `classes6/android/os/`; skips classes already present), applies `FRAMEWORK_METHOD_PATCHES` (body → `XdConfig` call) + `FRAMEWORK_INSERT_PATCHES` (insert after invoke), reassembles with `tools/smali.jar` and swaps the dexes back into the jar (other entries byte-identical, atomic replace). Missing files/methods only warn. Needs `java` (CI: `default-jre-headless`). Source tree is `unpacked_port/` in port mode, `unpacked_stock/` in mod mode (`patch_root`). LIMIT: jars are v3.0.10 (latest) — dex 041 is attempted, 042+ fails fast (no valid `--api`; 36+ writes zeroed headers). Every dex is verified after rebuild (magic + class count vs intake, since both tools exit 0 even on failure).
4f. Same `patch_jar_smali()` on `system_ext/framework/miui-services.jar` (under `patch_root`) with `MIUI_SERVICES_METHOD_PATCHES` (void bodies, no `XdConfig` call) + `MIUI_SERVICES_START_PATCHES` (insert secure-flag bypass block at the start of `notAllowCaptureDisplay`, matched by name + descriptor + body markers, unique `:bypass_secure_flag` label since baksmali renumbers `:cond_N` itself) + `MIUI_SERVICES_REPLACE_PATCHES` (literal field swap `IS_INTERNATIONAL_BUILD` → `IS_MIUI` for notifications on Chinese ROMs; no dsv dir yet — injection skips gracefully). All dsv rules apply to hos3 and hos4 alike (no version branching).
4g. Same `patch_jar_smali()` on `system/system/framework/services.jar` (under `patch_root`) with `SERVICES_METHOD_PATCHES`: `checkUpgradeKeySetLocked` + signature-match methods (keep original `.registers`, body → `XdConfig` call), `checkDowngrade` overloads (void stubs), `<clinit>` (full custom block forcing `ALLOW_NON_PRELOADS_SYSTEM_SHAREDUIDS=true`). Rules support fixed or kept registers plus custom body lines. `SERVICES_START_PATCHES` (secure-flag bypass at method start: empty-list variant for `WindowManagerService.notifyScreenshotListeners`, false variant for `WindowState.isSecureLocked`) + `SERVICES_NEW_METHODS` (brand-new `WindowState.isBypassSecureFlag()` reading `persist.sys.secure_flag`, inserted before `isLegacyPolicyVisibility`, skipped if already present). All three jar steps run only with `--dsv yes` (default; workflow `choice` input `dsv: "yes"|"no"`); `"no"` skips them entirely.
4h. `move_data_app_to_app()`: moves `product/data-app/*` into `product/app/` on the build tree (`patch_root`), merging dirs recursively via `merge_tree_into()` (existing entries replaced). Runs last, right before the rebuild, so debloat leftovers, DSV and modded apps all land in `app/`; no-op when `data-app/` is absent.
4i. `build_sidecars()`: writes `<part>.fs_config` + `<part>.file_contexts` next to each target `.img`, but only for erofs→ext4 conversions (the only ext4 built from erofs originals; native ext4 keeps the legacy build). `fs_config` = `/ 0 0 0755` + `<part>/<rel> uid gid mode [capabilities=0x..]` walked live from the final tree (symlinks skipped); `file_contexts` = `/` + own `etc/selinux/*_file_contexts` + plat/vendor fallbacks (specific-first, dedup), exact paths converted to `(/.*)?` pattern form (`+` escaped) since this lookup only matches patterns, plus explicit `lost+found` entries (mke2fs creates it, e2fsdroid fails fast on a miss) and a `$`-anchored `/<part>` entry for the mountpoint itself (covered by no stock pattern — label dumped from the tree root, `system_file` fallback). Runs on final trees right before the rebuild; missing sources only warn (→ legacy build).
5. `rebuild_partition_images()`: rebuilds `.img` in place from (patched) trees — port mode: port list → `extracted_port/`, `STOCK_PARTITIONS` only → `extracted_stock/` (donor extras `product`/`system_ext` in `unpacked_stock/` are never rebuilt); mod mode: full `MOD_PARTITIONS` set → `extracted_stock/` from the single stock tree. Format matches original by magic: erofs via `mkfs.erofs -z<EROFS_COMPRESSOR>`, ext4 via vendored AOSP `tools/mke2fs` (empty fs: `-L -I 256 -N <lines+8> -M /<part> -m 0 -b 4096`, journal KEPT — diverges from packer/UKA `^has_journal` deliberately) + `tools/e2fsdroid -e -T1230768000 -C -S -f -a` (populate/label; `-s` dedup only for non-RW) when sidecars exist, else legacy `mkfs.ext4 -d` (size = max(original, tree*1.1+32MB)). Partitions in the `--ext4-rw` set are forced to ext4 regardless of original format, sized tree + free_mb + 128MB margin with `-m 0 -b 4096` (no root reserve so the free MBs are really visible; explicit `-b` because mke2fs silently picks 1K blocks on small filesystems); anything outside the set keeps legacy behavior. Build goes to `<name>.img.new` + atomic rename, so failures keep the old image.
5b. `main()` deletes `unpacked_stock/` + `unpacked_port/` right after the rebuild — nothing below uses them, and lpmake needs ~super_size bytes free next.
6. `repack_super_image(stock_dir, port_dir, ...)` [+ `mod_partitions` in mod mode]: logs every image size + `df` of the output dir, then fail-fast `RuntimeError` (clear message) when free < super+512MB — without it lpmake dies with cryptic `sparse_file_write failed (error code -22)`. `lpmake --metadata-slots 3 --virtual-ab` (no `--sparse` — raw `super.img`), groups `qti_dynamic_partitions_a` (same size for `_b`), 4096-byte alignment, tight packing (groups fit the partitions exactly, super = group total + 1MB lpmake metadata minimum — proven locally: anything less fails with exit 70; no snapshot padding, no GiB rounding). lpmake output is captured (it probes every raw image as sparse → "Invalid sparse file format" noise is expected and harmless; only tail shown on failure, plus `df` at failure). Every partition is added twice: `<name>_a` with the real image, `<name>_b` as empty size-0 placeholder (no `--image` — unpacks as 0-byte file). Partition attr is `none` (not `readonly` — matches stock VAB + UnpackerSuper/UKA packing; `readonly` is for retrofit devices). Group sum may exceed super size; allowed under `--virtual-ab` (COW).
7. `assemble_package()`: fresh copy of committed `template/` → `package/`, `super.img` split into exactly 54 sparse chunks `images/super.img.0..53` (UKA/img2simg method, pure-Python port in `split_file()`: each chunk = sparse header + DONT_CARE offset + RAW data, so fastboot/recovery place every part correctly; raw slices would all land at offset 0. Sizing is exactly UKA — chunk = ceil(size_in_MB/54) whole MB, last takes the remainder (53 full + smaller last); names unpadded to match the scripts). `package_type="universal"` keeps `META-INF` (updater-script + update-binary, OTA metadata copied over `META-INF/com/android/` — port metadata in port mode, stock metadata in mod mode); `"fastboot-only"` deletes the whole `META-INF` dir and skips the metadata copy.
8. `create_recovery_zip()`: packs `package/` into `HyperOS-<port|mod>-duchamp-<ver>[-fastboot-only].zip` with DEFLATE-9 (max). The universal ZIP is flashable in TWRP/OrangeFox (updater-script + ARM update-binary already in `template/`); the fastboot-only ZIP is a plain archive — unzip and run the install scripts. CI uploads only the ZIP (`super.img` stays local to the run for chunking).

## Hardcoded inputs
- Stock (duchamp, HyperOS 3): `odm vendor odm_dlkm system_dlkm vendor_dlkm` (+ extras `product system_ext`, dumped/unpacked for reference only, never packed into super)
- Port (chagall, HyperOS 4): `mi_ext product system system_ext`
- Mod (`--mode mod`): full stock set `MOD_PARTITIONS` = `STOCK_PARTITIONS` + missing `PORT_PARTITIONS` names (all 9 from `STOCK_URL`, same order as the port super layout)
- Firmware URLs (`STOCK_URL`/`PORT_URL`) and mod-set URLs (`HOS3_MOD_URL`/`HOS4_MOD_URL`, GitHub release assets) are constants at top of `autoporter.py`.
- HyperOS `system.img` root contains a nested `system/` dir (`unpacked_port/system/system/app/...`, SAR-style). `moddedapps_hos*/system/system/...` mirrors it — the extra level is correct, do not "flatten" it. Other partitions (`product`, `system_ext`, ...) are flat at root.
- EROFS rebuild uses `EROFS_COMPRESSOR = "lz4hc,9"` (fast + safe; `"lzma,9"` also readable on the 6.1 kernel since MicroLZMA needs 5.16+, but builds much slower). Do NOT switch to deflate: it needs 6.6+ — unreadable images = bootloop.

## Gotchas
- `tools/` holds Linux x86-64 ELFs (`lpmake`, `lpunpack`, `payload-dumper-go`, `chunk_split`, AOSP `mke2fs`, `e2fsdroid`, dev-build `fsck.erofs` with xattr restore + killpriv-order fix) + Java jars (`baksmali.jar`, `smali.jar`, `apktool.jar`) committed to repo — ELFs won't run on Windows/macOS; use WSL2 or CI. `lpunpack` is currently unused. `lpmake` is a modern build (android-15 line, handles images >= 4GiB) and needs only system libc — the previous ancient static blob crashed with `sparse_file_write failed (error code -22)` on any 4GiB(-exact) dense data run (32-bit length wrap → zero-length chunk → `mmap(0)` → EINVAL, exit 73; proven with a local 4GiB-exact repro). Do NOT downgrade it.
- `7z` must exist for non-standard GDrive archives; `shutil.unpack_archive` alone is insufficient. Do NOT use `7z x` for ext4 images — it rewrites absolute symlink targets; `debugfs rdump` preserves them.
- No `extract.erofs` exists upstream (erofs-utils ships only `dump/fsck/mkfs.erofs`) — extraction is `fsck.erofs --extract`, which exists in both 1.7.1 (CI noble) and 1.9. Do NOT switch to `dump.erofs --cat`: it is missing in 1.7.1 and would break CI.
- `tools/` holds only what apt cannot provide (`lpmake`, `lpunpack`, `payload-dumper-go`, `chunk_split`, Java jars, plus `e2fsdroid`, AOSP `mke2fs` and the xattr-capable dev `fsck.erofs` for the contexts pipeline). Everything else (`dump`/`mkfs.erofs`, `simg2img`, `debugfs`, `7z`, JRE) comes from the apt list in `port.yml` — do not vendor them. `dsv/` (smali sources injected into jars, e.g. `XdConfig`) IS committed like `template/`.
- CI frees disk first (removes dotnet/android-sdk/ghc/boost, `docker image prune`) — full local runs need similar headroom.
- Outputs (`*.zip *.img *.bin`, `moddedapps_hos*/`, `extracted_stock/`, `extracted_port/`, `unpacked_stock/`, `unpacked_port/`, `package/`, `port_meta/`) are gitignored; only `super.img` is uploaded as artifact. `template/` IS committed (negations `!template/**/*.img|zip` keep its payload visible to git despite the rules above).
